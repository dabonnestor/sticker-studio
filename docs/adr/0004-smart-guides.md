# Smart guides

Status: accepted

**What it is**: interactive alignment guides with magnetic snapping shown while dragging an object on the stage — a visual and positional aid for laying out a Document. Move-only v1: guides and snapping engage during drags, never while scaling or resizing.

**Interaction model**: the moved object carries six reference points — left, center-x, and right on x; top, middle, and bottom on y (the object's four corners and center; a rotated object aligns by corner, not by AABB edge — the extension's native geometry, accepted for v1). Targets are everything else with a bounding box: every other object — Locked, Text, and Group included, a Group as one whole box, never its children — plus the Document's four edges and its center. When 2+ objects move together, the moved object is the selection's union box (the ActiveSelection); its members are never targets. The tolerance is a flat 6 screen px (named constant) — snap engages at ≤6 px and releases the instant it exceeds 6 px, no hysteresis; boundary oscillation at the exact threshold is accepted for v1. Alt/Option mid-drag suppresses the Snap while the Smart guides stay visible. Guides are 1 px full-workspace-extent lines in the periwinkle selection family — dashed `rgb(178,204,255)` while near, solid `rgb(100,100,255)` when snapped — with coincident lines deduped to one.

**Snap resolution**: per axis, the nearest alignment within tolerance wins, and both axes engage independently — a corner approach lands a crosshair pair of solid guides. When several targets offer the same delta on an axis, every equidistant line shows: the line the object actually snapped to is solid, the rest dashed, identical coordinates render one line; the tie-break is the engine's collection order (deterministic — canvas object order — accepted as-is for v1). An alignment is **tautological** — and skipped — when it would sit permanently at the moved object's own reference point: the target's coordinate coincides with the object's own reference coordinate at drag start (within a sub-pixel tolerance) on an axis the drag does not move. This is the full-span case — a full-width object's edges and center are permanently coincident with the Document's, so without the skip its own edges (and a line through its own body) would show solid guides for the whole drag. The skip is narrow: an alignment to a nearly-covered target whose coordinate is distinct from the object's own (e.g., a large object's edge meeting a small object's edge just under its own body) still shows.

**Engine**: the `aligning_guidelines` extension (`fabric/extensions`, v7.4.0) as the base — it computes per-axis min-distance lines from the moved object's five points against every target's corner+center points, snaps via `setXY` inside `object:moving`, and caches the lines as JSON strings in `verticalLines`/`horizontalLines`. A repo subclass, `SmartGuides` in `src/fabric/smart-guides.ts`, overrides exactly four methods:

- `getObjectsByTarget` — the only custom target logic: Groups added as whole boxes via their `getCoords()` bbox (the default unpacks them to children); four 0-thickness rects fabricated at the Document edges plus one tiny rect at its center, constructed once and never added to the canvas (no render/serialization/selection side effects; detached `getCoords` works via lazy `aCoords`); the default's exclusions kept (off-screen, invisible, the moved object's members); plus the tautological skip — for each axis, targets whose alignment coordinate coincides with the moved object's drag-start reference coordinate are dropped when that axis is not being moved.
- `scalingOrResizing` → no-op (move-only v1).
- `afterRender` → no-op (its `contextTop` paint is replaced; `beforeRender` keeps the default — it clears the now-unused top context).
- `moving` — Alt/Option suppression via revert-after-snap: snapshot `left`/`top` + `originX`/`originY`, call `super.moving(e)`, restore and `setCoords()` (**the origin reset is required** — the extension's `setXY` routes through `setPositionByOrigin` and mutates origin). Records the per-axis snapped flags (position after `super.moving` vs the snapshot) and the drag-start reference snapshot the tautological skip reads.

**Painting**: the repo paints the guides on the workspace overlay, not the extension's `contextTop`. A repo `after:render` handler reads the `verticalLines`/`horizontalLines` caches — entries `{origin, target}` in scene coordinates, the line's coordinate being `target.x`/`target.y` — and paints full-extent periwinkle guides under the viewport transform (identity today; zoom-ready — the extension already divides its margin by zoom, so the 6 px stays screen-correct when zoom lands). Per axis, the first cache entry (the `setXY`-triggering one, in insertion order) is solid and the rest dashed; a suppressed axis (Alt) paints all its lines dashed — nothing snapped. `StageCanvas`'s private `prepareOverlay` (`src/fabric/stage-canvas.ts:332`) becomes the public paint seam, `_drawSelection`'s mirror (`:367`) the precedent; `finalizeOverlayFrame`'s keep-rule (`:309`) gains a "guides painted this frame" flag.

**Lifecycle**: `dispose()` unbinds the extension's six listeners plus the wrapper's own (the painter hook and the drag snapshot), pinned for the canvas-rebuild lifecycle. Fabric is exact-pinned (7.4.0); the extension's class API moved in v7 and future majors may move it again — the subclass isolates every touchpoint in one module. Snapping produces ordinary move gestures: one undoable step per drag (ADR 0001); guides are view state — never serialized (ADR 0002), never undoable steps. Glossary terms: **Smart guide**, **Snap**, **Snap target**, **Snap suppression** (CONTEXT.md).

## Considered Options

- **Fully custom engine** — rejected: the gaps concentrate in the designed seam (`getObjectsByTarget`) plus painting the repo already owns; a custom engine would own ~200 lines of edge cases (rotation, scale, flips, unions, locked objects) the extension already handles, and would need to extract the module-private `align.ts` math (`documentBounds`/`unionBox`).
- **Single-nearest alignment across both axes** (one axis engages) — rejected: more code, artificial feel, and no major design tool gates like that; crosshair is engine-native.
- **Winner-only tie display** — rejected: the dashed equidistant companion communicates "an alternative alignment sits at the same distance".
- **Hysteresis threshold** — rejected for v1: flat is engine-native; oscillation only bites when the cursor hovers the exact threshold; the named constant keeps hysteresis a one-knob change if jitter reports justify it.
- **Accepting the perpetual full-span guides** — rejected: full-bleed stickers are a real use case; permanent solid lines at the object's own edges (and through its body) are noise.
- **Skipping every target inside the moved object's span** — rejected: also kills legitimate flush-alignments to nearly-covered targets, which the narrow tautological skip keeps.

## Consequences

- Build sessions implement from build-spec §17 without re-deciding; ADR 0004 and §17 are the contract.
- Zoom (future): painting is viewport-space by construction, but tolerance scaling and guide density at high zoom stay untuned until zoom ships (map fog).
- The fabricated document objects must never enter the canvas — no serialization, selection, or render side effects.
